# Juxtopposed-inspired design for Pomegranate

The user explicitly likes Juxtopposed's designs. Translate that preference into an original, coherent product interface. Read references/sources.md when selecting inspiration or explaining attribution. It distinguishes observed material from our own recommendations. No official Juxtopposed agent skill was found in the public sources checked on 2026-10-05; this does not establish that none exists.

## Interpret the preference without freezing a style

Her portfolio, Realtime Colors, and Stack Sorted use different visual languages. Do not equate the preference with mandatory pixel fonts, purple, dark mode, glowing borders, or a particular dashboard layout. The useful direction is deliberate visual identity, contextual palette exploration, clear component hierarchy, and expressive interaction where it serves the product. These are our working interpretations, not quotations of her methodology.

For a new screen, identify the primary job and the information users need at that moment. For a redesign, identify the actual usability problems before changing styling. Carry forward the product's useful conventions. If the user supplies a favorite video or Figma frame later, inspect that specific reference and revise this direction rather than claiming the current guide already captures it.

## Explore in context

- Show a small number of meaningfully different directions when visual direction is unresolved. Explain how each fits the actual product; avoid variations that only swap accent colors.
- Compare palettes on a representative product screen, including dense content, controls, and error states. Realtime Colors is a useful optional exploration tool. Start with semantic roles such as canvas, surface, text, muted text, primary action, and status; distinguish brand colors from functional feedback.
- Compare type at realistic title, navigation, body, label, and data sizes. A display treatment can provide identity while working UI remains readable. Do not copy the tool's default font or palette as a required brand decision.
- Use Stack Sorted to inspect a specific element when inspiration is needed. Identify the original creator of each example; curation does not make every design Juxtopposed's work.

## Adapt to a large React product

Create reusable tokens and interaction patterns before styling many unrelated screens. Keep navigation, search/filter behavior, form labels, focus, disabled states, loading, errors, and notifications consistent. Design with realistic long names, large collections, and missing data. A beautiful promotional hero is not evidence that the application's working screens are usable.

Spend expressive detail where it clarifies identity or feedback: selection, action confirmation, opening a panel, or a distinctive but legible visual motif. Keep high-frequency tasks immediate. Respect reduced-motion preferences and provide keyboard/touch equivalents for hover interactions.

Use shared component variants and composition rather than independent per-page CSS recipes. Keep business rules out of generic visual primitives. Follow the project's FSD decisions instead of inventing a separate design folder architecture.

## Critique the result

Inspect the implemented screen visually at a narrow and a desktop viewport, and walk through its primary task. Check hierarchy, text wrapping, contrast, focus, state changes, and whether expressive details distract from the task. Report what was actually checked. Use the installed web-design-guidelines skill for a requested formal UI audit.

Persist chosen tokens, examples, and rationale in docs/design.md when a direction is established. This skill stores a preference and process, not the final design specification.
